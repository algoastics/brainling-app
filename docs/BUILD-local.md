# Local release build (no EAS), Ahsan's Mac

Not run by the author of this file: these are the exact steps, taken from the project config
(`app.json`, the generated `android/app/build.gradle`) and `docs/TESTING-phase0.md` section 0.

## Working rules for this folder

- There is ONE local folder: `~/Documents/"Algoastics Github"/brainling-app`. Do not make extra
  copies or worktrees.
- `main` is never committed to directly. Work on a branch (`docs/<name>`, `fix/<name>`) and merge
  it yourself.
- Run `npm install` first (a fresh checkout or after `package-lock.json` changes), so
  `node_modules` matches the lockfile.
- `android/` is git-ignored and currently removed, so `expo prebuild --clean` starts from a clean
  slate and regenerates it.

## Build the APK and install it on your phone

1. Prerequisites (once):
   - JDK 17 (Zulu) at `/Library/Java/JavaVirtualMachines/zulu-17.jdk/Contents/Home`.
   - Android SDK at `~/Library/Android/sdk` (platform-tools for `adb`, platform 36 or newer).
     `app.json` sets `targetSdkVersion` 36 through expo-build-properties; `compileSdk` stays at the
     React Native default (37), so no override is needed. Regenerate `android/` to pick it up.
   - On the phone: Developer options -> **USB debugging** on, plug in, accept the RSA prompt.
   - Check it is seen: `~/Library/Android/sdk/platform-tools/adb devices` must list the serial
     as `device` (not `unauthorized`).
2. Run `npm install` if you have not yet, then regenerate the git-ignored `android/` folder (needed after any native, config-plugin or
   `app.json` change, and for the new service description text):
   ```bash
   cd ~/Documents/"Algoastics Github"/brainling-app
   npx expo prebuild --platform android --clean --no-install
   ```
3. Build the arm64 release APK:
   ```bash
   cd android
   JAVA_HOME=/Library/Java/JavaVirtualMachines/zulu-17.jdk/Contents/Home \
   ANDROID_HOME=$HOME/Library/Android/sdk \
   ./gradlew assembleRelease -PreactNativeArchitectures=arm64-v8a
   ```
4. The APK is at `android/app/build/outputs/apk/release/app-release.apk`.
5. Install over USB (replace the serial; `RF8X605YFVM` is only an example):
   ```bash
   ~/Library/Android/sdk/platform-tools/adb -s RF8X605YFVM install -r --user 0 app/build/outputs/apk/release/app-release.apk
   ```
   Run it ONCE. `--user 0` installs for the phone's main user only, so a Samsung Dual Messenger
   (`DUAL_APP`), Secure Folder or work profile user never gets a second copy. `-r` keeps the app
   data. If it fails with `INSTALL_FAILED_UPDATE_INCOMPATIBLE`, the debug key changed (every
   `--clean` prebuild makes a new one): `adb -s <serial> uninstall com.algoastics.thumbwell`, then
   install again. For a clean first-run test, uninstall first as well.
6. If an icon still shows twice, run the read-only check (never installs or removes anything):
   ```bash
   cd ~/Documents/"Algoastics Github"/brainling-app && scripts/check-android-identity.sh RF8X605YFVM
   ```
   It checks the manifest (one LAUNCHER filter, no alias), the APK (one launchable activity, one
   package id) and lists the phone's users, the Thumbwell/Brainling packages and launcher entries
   per user. One package id and one launcher entry means the duplicate is the phone's launcher.

## Signing: this APK uses the debug key

The generated `android/app/build.gradle` has `release { signingConfig signingConfigs.debug }` (the
comment there says to generate your own keystore for production). The debug keystore is
`android/app/debug.keystore`, which Expo regenerates on every `--clean` prebuild. Fine for
side-loading on your own phone. **Not acceptable for Google Play.**

## Can the Play AAB be built locally?

Yes. From `android/`, with the same `JAVA_HOME` and `ANDROID_HOME` and without the architecture flag
(Play wants all ABIs):

```bash
./gradlew bundleRelease
```

Output: `android/app/build/outputs/bundle/release/app-release.aab`.

But **do not upload that AAB as it is**: it is signed with the debug key. Play needs a bundle signed
with an **upload key** that you own:

1. Create the upload keystore once and back it up outside the repo (never commit it):
   ```bash
   keytool -genkeypair -v -storetype PKCS12 -keystore ~/thumbwell-upload.keystore \
     -alias thumbwell-upload -keyalg RSA -keysize 2048 -validity 10000
   ```
2. Put the passwords in `~/.gradle/gradle.properties` (not in the repo), for example
   `THUMBWELL_UPLOAD_STORE_FILE`, `THUMBWELL_UPLOAD_STORE_PASSWORD`, `THUMBWELL_UPLOAD_KEY_ALIAS`,
   `THUMBWELL_UPLOAD_KEY_PASSWORD`.
3. Make the release build use them. `android/` is regenerated by every prebuild, so do not hand-edit
   it: add a small Expo config plugin (like `plugins/withReleaseBlockedPermissions`) that adds a
   `release` signing config reading those properties and points `buildTypes.release.signingConfig`
   at it. This plugin does not exist yet.
4. In Play Console, use **Play App Signing**: the first upload enrols your upload key, and Google
   keeps the app signing key. Keep the upload keystore safe; a lost upload key needs a Google
   reset request.
5. Before the first upload also: the Play declaration, disclosure text and listing wording for the
   on-screen counter (F18, D42) still need Ahsan's and legal review, and the debug-signed rules key
   (`brainling-dev-2026-10`) must be replaced with a production key.

## Build-time variables (names only, never values in the repo)

Set them in the shell before step 2 (`expo prebuild`) and step 3. Only `EXPO_PUBLIC_*` values reach
the JS bundle, and the bundle is public: never put a secret there. `.env*` files are git-ignored and
gitleaks blocks committing secrets.

| Name | Visibility | Used by |
|---|---|---|
| `EXPO_PUBLIC_REVENUECAT_ANDROID_KEY` | public SDK key | M8 billing |
| `EXPO_PUBLIC_SENTRY_DSN` | public DSN | M11 crash reporting |
| `SENTRY_ORG`, `SENTRY_PROJECT`, `SENTRY_AUTH_TOKEN` | auth token is a secret | source-map upload |
| `EXPO_PUBLIC_POSTHOG_KEY`, `EXPO_PUBLIC_POSTHOG_HOST` | public project key | M11 analytics |
| `THUMBWELL_RULES_URL` | public URL, optional | M1 remote detection ruleset |

`THUMBWELL_RULES_URL` is read at prebuild by the `thumbwell-core` config plugin
(`modules/thumbwell-core/app.plugin.js`) and written to the manifest as
`com.algoastics.thumbwell.RULES_URL`. It must be an `https://` URL serving a signed envelope made by
`scripts/rules/sign-rules.mjs`; prebuild fails on any other scheme. Unset: the app uses only the
bundled signed ruleset. The trust comes from the Ed25519 signature, not the URL, and the signing keys
are never stored in the build environment (see `docs/modules/M01-detection.md`). Changing it needs
a new build. Set `SENTRY_DISABLE_AUTO_UPLOAD=true` to build without the Sentry token.
